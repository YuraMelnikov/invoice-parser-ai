# AGENTS.md — правила проекта «Оператор склада»

Главный источник правил для ИИ-агента, работающего с этим проектом.
**Перед любой задачей прочти:** этот файл → `README.md` (цель + decision log) → `docs/DOD.md`.
Остальные документы ссылаются сюда, а не дублируют: правила живут только здесь.

## Цель проекта

Разработать n8n-решение автоматической обработки приходных накладных в виде
PDF-сканов без текстового слоя: от появления файла до структурированных данных.
Зафиксировано владельцем 2026-10-04.

## Зоны контекста (как устроен этот проект)

| Зона               | Где живёт                                               |
| ------------------ | ------------------------------------------------------- |
| Правила проекта    | этот файл (AGENTS.md)                                   |
| Текущая задача     | шаблон постановки — `docs/TASK_TEMPLATE.md`             |
| Долгая память      | decision log в `README.md` + ADR в `docs/decisions/`    |

## Текущий статус

Этап 0 — скелет контекста. Реализация не начата: код, инфраструктура,
миграции и workflow отсутствуют. Стек зафиксирован частично: оркестратор — n8n
(требование цели); остальные компоненты выбираются через ADR.

## Инварианты (правила, которые действуют всегда)

1. **Нет записи — нет решения.** Любое осознанное решение (стек, модель, порог,
   схема данных, компромисс) фиксируется: ADR в `docs/decisions/` + строка в
   decision log `README.md` (дата, решение, обоснование).
2. **Идемпотентность по умолчанию.** Любой шаг обработки безопасен при повторном
   выполнении: upsert вместо insert, `IF NOT EXISTS` в миграциях, повторный запуск
   не плодит дубли.
3. **Новый компонент = ADR.** Выбор СУБД, моделей, библиотек, пороговых значений —
   только через запись в `docs/decisions/`.
4. **Маленькие проверяемые шаги.** Каждая задача принимается по `docs/DOD.md`;
   «сделано» без проверки — не сделано

## Тестирование и экономия контекста

* Эталон (`expected.json`) — источник истины. Подгонять эталон под фактический
  результат запрещено; эталон меняется только с одобрения владельца.

## Безопасность (красная граница)

* Деструктивные действия (удаление данных, сброс volume, перезапись прод-таблиц) —
  только по явной инструкции владельца в текущей задаче.

## Что не трогать

* Этот файл (AGENTS.md): агент не меняет правила сам; правки предлагаются
  владельцу текстом или оформляются ADR.

* `tests/fixtures/*.expected.json` — эталон меняет только владелец.

* Закрытые ADR не переписываются. Отмена решения = новая ADR со ссылкой на старую.

* Файлы вне scope текущей задачи (scope определён в постановке по
  `docs/TASK_TEMPLATE.md`).

## Как работать с задачей

1. Получил задачу → проверь, что есть scope и DoD; нет — уточни у владельца по
   `docs/TASK_TEMPLATE.md`.
2. Перед изменениями → прочти decision log: решение, которое ты собираешься
   принять, могло уже быть принято (или отвергнуто с обоснованием).

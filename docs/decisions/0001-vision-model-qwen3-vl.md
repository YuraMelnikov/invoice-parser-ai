# ADR-0001. Vision-модель: Qwen3-VL 8B вместо Qwen2.5-VL 7B

- Дата: 2026-10-06
- Статус: принято

## Контекст

Пайплайну нужна vision-модель в двух местах: основная экстракция позиций
накладной из растрированных страниц и бинарная проверка ориентации страницы
в pdf-render (`ORIENT_MODEL`). Текстовая модель не подходит: вход — только
изображения.

## Решение

Использовать `qwen3-vl:8b` (Ollama) как единственную vision-модель стека.
Заменяет ранее планировавшийся `qwen2.5vl:7b` в:

- `docker-compose.yml` — список `ollama pull` в init-контейнере;
- `shared/pdf-render/app.py` — дефолт `ORIENT_MODEL`.

## Обоснование

Qwen3-VL — более новое vision-поколение при том же классе размера (8B),
качество распознавания документов выше предшественника. Решение владельца
2026-10-06.

## Последствия

- Обе точки потребления vision берут одну и ту же модель — один вес в
  `ollama_storage`, один прогрев.
- Тег модели фиксируется в двух файлах; при смене модели менять оба
  (compose + `ORIENT_MODEL`) и обновлять эту ADR новой записью.

## Уточнение 2026-10-06

Фактическое имя модели в Ollama после `pull qwen3-vl:8b`:
`qwen3-vl:8b-instruct-q8_0` — API принимает только полное имя, короткий тег
даёт 404. Короткий тег обновлён на полный в compose (pull), `ORIENT_MODEL`,
worker и `run_eval.py`. Побочный эффект рассинхрона: VLM-проверка поворота
в pdf-render при 404 молча отдаёт дефолт (270°) — маскирует проблему;
при смене модели проверять `rotation` на test_03.

# Задача 002. Линковка позиций накладных со справочником ERP (embeddings → Qdrant → matcher)

- Дата постановки: 2026-10-07
- Статус: **выполнена 2026-10-07** (принято владельцем, см. DoD ниже)

## Цель

Каждая распознанная позиция накладной автоматически связывается с кодом
номенклатуры ERP по смысловой близости наименований (bge-m3 → Qdrant):
код пишется прямо в `docs.invoice_items.sku_code`, факт обработки строки
матчером — флаг `link_processed` (ставится всегда: и при успехе, и при
«не найдено»).

## Решения владельца (2026-10-07)

1. `exportImport.dbo.CurrentOrder` — справочник номенклатуры (имя
   игнорируем), ~365 строк.
2. Результат — в строку `docs.invoice_items`: `sku_code` + boolean-флаг
   обработанности.
3. **Без кэша справочника и без очереди review.** Каждый цикл линковки
   запрашивает свежее состояние справочника ERP. Нашёл → `sku_code` +
   `link_processed=true`. Не нашёл → просто `link_processed=true`
   (`sku_code` остаётся NULL). Переиндексация полная — 365 строк, дёшево.
4. Линковка один-к-одному: позиция → top-1 SKU.
5. **Эмбеддинг позиций — отдельным workflow (Invoice-004), не в Worker**
   (обсуждение 2026-10-07): сбой Qdrant/embed внутри Worker уронил бы весь
   документ и обнулил ~10 мин распознавания (error-ветка — backlog-задача
   003); отдельный тик изолирует сбой. Лаг до 10 мин для складского потока
   несущественен.
6. **Id точки Qdrant для позиции — детерминированный UUID v5 от
   `(file_name, line_no)`**, а не `item_id`; кэш `item_embeddings`
   ключируется так же. Иначе переобработка файла (delete+insert в воркере →
   новые item_id) плодит точки-сироты в коллекции.

## Предлагаемое решение (процесс пошагово)

### Шаг 1. Миграция `sql/003_embeddings.sql` (идемпотентна)

- `docs.item_embeddings (file_name, line_no PK, model, created_at)` — кэш
  «вектор позиции записан в Qdrant», ключ `(file_name, line_no)` — устойчив
  к переобработке файла (решение владельца 2026-10-07, п.6).
- `ALTER TABLE docs.invoice_items`:
  - `sku_code text` — результат линковки (NULL = не слинковано);
  - `link_score numeric` — score top-1 от матчера (диагностика;
    NULL = матчер строку ещё не видел);
  - `link_processed boolean NOT NULL DEFAULT false` — матчер строку
    отработал (независимо от результата).

Таблица `sku_embeddings` из наработки **не нужна**: справочник
переиндексируется полностью каждый цикл.

### Шаг 2. `Invoice-004_Embeddings` ← переработка `tmp/embeddings.json`

Тик 10 мин. Батч 32 позиции без эмбеддинга → bge-m3 (`/api/embed`) →
upsert в коллекцию `invoice_items` → запись кэша. Креды Postgres —
`uSXpwajUhahtQd3N`. Error-ветки из наработки сохранить.

### Шаг 3. `Invoice-005_SKU-sync` ← переработка `tmp/erp.json`, полный рефреш

Тик 1 час. Читает ВЕСЬ справочник ERP (MSSQL, ~365 строк) → bge-m3 →
upsert всех точек в `sku_catalog` (UUID v5 от кода) → удаление точек,
чьих кодов больше нет в ERP (scroll + delete по payload.code). Без
кэш-таблицы. MSSQL-нода — креды «Microsoft SQL account».

### Шаг 4. `Invoice-006_Matcher` — новый workflow

Тик 10 мин (после embeddings). Позиции `link_processed=false` с готовым
эмбеддингом → search `sku_catalog` top-1 → update `invoice_items`:

- всегда: `link_score = score`, `link_processed = true`;
- если `score ≥ T1`: дополнительно `sku_code = код`;
- если `< T1`: `sku_code` остаётся NULL.

Идемпотентно: повторный тик берёт только `link_processed=false`.

Начальное T1 = 0.85 — калибруется на шаге 5, утверждает владелец.

### Шаг 5. Калибровка порога (до включения 006 в прод)

Скрипт в `tmp/`: прогон поиска по 23 позициям эталонов → матрица score
(top-3 на позицию) → владелец размечает/утверждает эталон связей
(`tests/fixtures/linking.expected.json` — черновик агента, утверждение
владельца) → порог T1 фиксируется в ADR-0004.

### Шаг 6. Контроль неслинкованного

SQL в pgAdmin (запрос добавить в RUNBOOK §10) — «отработано, но кода нет»:

```sql
SELECT ii.id, i.file_name, ii.item_name, ii.link_score
FROM docs.invoice_items ii
JOIN docs.invoices i ON i.id = ii.invoice_id
WHERE ii.link_processed = true AND ii.sku_code IS NULL
ORDER BY ii.link_score DESC;
```
